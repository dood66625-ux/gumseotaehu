# 프록시 접속자 정보·반복 요청 보호 준비

2026-11-21. 소프트웨어 연결과 향후 운영용 Caddy 예제만 준비했다. 현재 서버/방화벽/WAF/환경변수를 변경하지 않았으며 5.3.3은 진행 중이다. 이 기능은 관리형 WAF나 네트워크 접근 차단을 대신하지 않는다.

기본 CLIENT_IP_PROTECTION 미설정/disabled에서는 IP 추론과 새 IP 제한을 하지 않고 기존 세션/전역 제한을 유지한다. trusted-proxy 모드를 명시하면64자리 소문자hex TRUSTED_PROXY_TOKEN을 요구한다. 다른 모드나 설정 누락은503, 프록시 인증/유효 IP 누락은403으로 거절한다. 인증이 실패한 IP 주장은 어떤 제한 버킷에도 반영하지 않아 타인의 버킷을 임의로 소모하지 못하게 한다.

앱은 Forwarded/X-Forwarded-For를 신뢰하지 않는다. 프록시가 덮어쓴 X-Gumseo-Client-IP와 X-Gumseo-Proxy-Token만 확인한다. 복수 IP/포트/IPv6 scope/공백/잘못된 주소를 거절하고 IPv6 축약·대소문자·IPv4-mapped 표기를 정규화한다. 원문 IP나 프록시 토큰은 DB/감사 로그에 넣지 않는다. 기존 limit()가 버킷 전체를 AUTH_SECRET으로 HMAC 처리한 뒤 카운터를 저장한다. 실제 활성화 전 개인정보 고지/보관 정책도 검토한다.

인증된 IP당 분당 전체API240회, auth/request·auth/verify·admin/login 합산15회, 결제·관리자 변경 요청 합산30회를 적용한다. 기존 주문/세션/MFA/전역 제한을 대체하지 않는다. 요청자 다수가 같은 NAT를 쓰는 상황과 IPv6 실제 경로에서 한도 적정성을 검증해야 한다. health 응답은 기존대로 프록시 인증 예외이며 새 한도로 보호하지 않는다. 별도 토스/메일 웹훅 경로도 이번 catch-all 변경 범위 밖이고 각자의 서명/원장 검증을 유지한다.

## 활성화 전 필수 조건

`deploy/iwinv/Caddyfile.operator-proxy.example`은 현재 merchant-review Caddyfile에 설치하는 파일이 아니다. 향후 운영 앱 호스트에서 검토할 최소 예제다. 현재 gumseo.kr/pay.gumseo.kr 심사·비공개 reader 경로를 교체하지 않는다.

- 앱 포트는 loopback 전용이어야 하고 외부에서 직접 접속할 수 없어야 한다. 프록시 인증값만으로 방화벽 검증을 생략하지 않는다.
- 고객/관리자/DB 키와 다른 전용64자리hex 토큰을 root 전용 파일에서 프록시와 앱 런타임에 각각 전달한다. Git·클라이언트 번들·응답·로그에 넣지 않는다. Caddy 환경변수 주입도 별도로 설정해야 한다.
- 프록시가 고객이 보낸 두 전용 헤더를 덮어쓰고 원래 소켓 remote_host를 넣는지 실제 요청으로 확인한다. 헤더의 단순 존재나 문자열 IP를 신뢰하지 않는다.
- CDN/LB가 앞에 있다면 remote_host는 실제 고객이 아닐 수 있다. 검증된 중계 경로 설계 없이 이 예제를 그대로 활성화하지 않는다.
- 운영 HTTPS/헤더 위조/직접 포트 접근/정상 로그인·결제 복귀/동일 NAT·IPv6/health·웹훅의 실제 동작을 검증하고 운영 WAF 정책과 결합해야 한다. 설정 오류 시 보호 API가 차단될 수 있어 점검 창과 되돌릴 설정을 준비한다.

## 검증과 한계

검증되지 않은 전달 헤더 무시·전용 인증 누락/변조/잘못된 설정 차단·단일 주소 검사·IPv6/IPv4-mapped 동일 버킷·민감 요청 버킷 연결4개와 전체 빌드를 검증했다. 실제 프록시/방화벽/WAF와 운영 부하를 검증한 것은 아니다. 실제로 활성화하기 전에는 운영 접속 보호 완료로 표시하지 않는다.

## 실제 로컬 프록시 통합 검증 (2026-11-21)

`npm run test:proxy`는 빌드된 앱과 실제 Caddy를 loopback 전용의 가상 환경에 띄우고 합성 DB·임시 자격증명을 정리한다. `CADDY_EXECUTABLE` 또는 기존 var/staging/tools/caddy가 필요하다. 비공개 Caddy 게이트가 전용 IP/토큰 헤더를 덮어쓰도록 연결했으며, 기존 비활성 검증 환경에서는 기본 disabled 값을 사용한다. 실제 운영 심사 Caddyfile은 바꾸지 않았다. 향후 운영 예제에는 환경/Git 파일 경로 차단과 요청 본문 1MB 제한도 포함했다. 이는 관리형 WAF 설치를 뜻하지 않는다.

실제 로컬 TLS 요청으로 위조 전용 헤더/XFF 덮어쓰기, 인증 없는 직접 API 접근403, 비loopback 인터페이스의 앱 포트 연결 거절, HMAC 버킷 저장·원문 IP/토큰 미노출, 인증15회/금융변경30회/전체240회 후429, 제한 후 health 정상 응답을 확인했다. 요청은 이 검증 환경만 대상으로 하며 실제 로그인·결제·발송은 하지 않는다. 향후 운영 예제의 Caddy 구문도 adapt로 확인한다.

운영 서버 SSH는 2026-11-21 재조회에서도 TCP22 Connection refused여서 서버 내부 방화벽·WAF·프록시 설치 상태와 외부 직접 포트 차단을 검증하지 못했다. 비공개 로컬 검증을 운영 현장 검증으로 세지 않으며 **5.3.3은 진행 중, 전체40/56=71.4% 유지**한다. SSH 복구는 서버 제공자 콘솔에서 ssh 서비스 리스닝/실제 SSH 포트와 인바운드 규칙을 확인해야 한다. 서버 콘솔 접속은 이 세션에 연결되어 있지 않다.
