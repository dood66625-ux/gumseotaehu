# 이메일 발송·복구 코어

2026-11-14. 실제 이메일 업체·SMTP·Gmail을 연결하지 않았으며 실제 고객 이메일을 발송하지 않았다. 가짜 MailGateway의 접수/조회/반송 응답과 합성 이메일만 사용한다.

## 발송 기록
- 기존 outbox와 수신 주소 스냅샷을 같은 트랜잭션에 저장. 수신 주소는 검증/주문/문의 기록에서 찾고 HMAC 일치 여부를 확인한 뒤 암호화한다. 주소를 해시에서 추측하지 않는다.
- 문의 답변을 위해 인증 기록이 만료된 뒤에도 필요한 연락처를 암호화해 문의와 연결한다. 구매 이메일 변경 시 연결된 문의 연락처도 함께 변경한다. 이 연락처의 법정 보존/파기 정책 확정은 남아 있다.
- 메시지는 허용한 거래용 템플릿만 사용. outbox의 자유 body/고객 문의·답변 원문을 그대로 HTML이나 외부 메일 본문으로 넘기지 않는다. 생년월일·차트·운명서·PDF 첨부 없이 인증 후 확인 경로만 제공한다.
- 인증번호는 본문에만 넣고 제목에 넣지 않는다. 만료/사용/새 요청으로 대체된 번호, 삭제/환불/수신 주소 변경 후의 오래된 운명서 안내는 발송 전에 취소한다. 출발한 메일을 원격 회수한다고 주장하지 않는다.

## 접수와 전달 구분
공급자의 send 응답은 accepted로만 기록한다. delivered는 공급자의 독립 조회 근거가 있을 때만 표시하고, 이것도 고객 열람/PDF 저장이나 법적 콘텐츠 제공 동의의 증거로 쓰지 않는다.

## 중복·오류·재시도
- 메일별 고정 식별자와 변경하지 않는 envelope를 사용. sender/origin/공급자 이름을 묶은 발송 설정이 달라지면 기존 기록의 발송을 거부한다. 공급자 이름은 실제 계정/프로젝트까지 구분하도록 어댑터에서 설정해야 한다.
- DB lease/세대 번호로 동시 작업/재시작/오래된 응답을 구분한다. 기본 10초 타임아웃과 AbortSignal을 제공한다. 실제 어댑터는 AbortSignal을 준수해야 하지만 이미 수락된 메시지를 취소했다고 해석하지 않는다.
- 응답을 못 받은 건은 재조회부터 수행. 공급자가 멱등키의 미접수를 독립적으로 보장하고 유효 기간 안임을 확인할 때만 같은 메시지/키로 재시도한다. 멱등키로 조회할 수 없는 공급자는 unknown을 반환해야 하며 보내지 않았다고 추정하면 안 된다.
- 알고 있는 provider ID도 조회 어댑터에 전달한다. 실제 업체별 조회·멱등 기간·응답 정합성은 실제 어댑터 구현/샌드박스 검증에서 확인해야 한다.
- 불명확/일시 실패는 backoff, 연속 6회 뒤 검토 상태. 실제 오류 본문/주소/인증번호/메시지를 로그나 last_error에 기록하지 않는다. 조회 실패가 이미 확인된 delivered/bounced/complained 상태를 되돌리지 않는다.
- 기본 공급자는 disabled이고 앱/기존 worker에 등록하지 않았다. 키만 추가해도 실제 발송되지 않는다.

## 반송·수신거부
알림 본문은 이미 연결된 provider ID의 조회 신호만 만든다. 원문의 delivered/bounced/complained 주장을 신뢰하지 않는다. 독립적이고 authoritative한 영구 반송/스팸 신고를 확인한 경우에만 수신 주소 HMAC을 억제 목록에 기록한다. 일시 반송은 전역 차단하지 않으며, 뒤늦은 낮은 단계 응답으로 억제를 해제하지 않는다. 자동 해제/업체 억제 목록 해제·이의 처리 정책은 미구현이다. 실제 웹훅 HTTP 파싱·서명 검증도 업체 선택 후 구현해야 한다.

## 백업·키 교체
모든 복구 사본은 세션/인증 요청을 폐기하고 진행 중 이메일 변경도 취소한다. 복구된 메일은 재조회 전 보류한다. 공급자 멱등 보존 기간 밖의 오래된 메일을 미접수로 추정해 재발송하지 않는다. 원본 DB/환경은 바꾸지 않고 주문/운명서 원문은 보존한다.

수신 주소/렌더링된 envelope/문의 연락처도 DATA_KEY 교체 대상이다. 인증메일 기록은 1일 후, 기타 로컬 outbox는 기존 7일 후 정리한다. 이는 법정 거래기록 보관을 대체하지 않는다.

메일 공급자의 최신 억제 목록, 백업 뒤의 이메일 변경/소비된 인증 정보/진행 상태를 모두 자동 동기화하는 완전한 재해복구 시스템은 아니다. 인증 정보 폐기와 발송 보류는 보수적인 기본값이며, 실제 운영 복구 전 원래 공급자 계정/설정 및 최신 이력을 확인해야 한다.

## 검증
기본 공급자 차단, 암호화/수신자/템플릿, 접수와 전달 구분, 응답 누락/동일 envelope 재시도/6회 실패 중단, OTP 만료·사용·대체, 환불 뒤 낡은 안내 취소, 동시 작업/lease 교체, 거짓 반송/일시·영구 반송·신고·역순 응답, 멱등 기간 만료, 설정 변경, 인증 기록 파기 뒤 문의 답변, 늦은 응답 뒤 삭제 기록 비복원, 백업의 인증 폐기/메일 보류, 키 교체, 트랜잭션 원자성/비동기 콜백 거부, 타임아웃을 합성 사례로 검사한다.

## 미완료
실제 메일 공급자·보안 키/서버 어댑터·SPF/DKIM/DMARC·서명된 실제 반송/스팸 알림·업체의 멱등/조회 보장 검증·worker 등록/모니터링·로컬 인증번호 열람 경로의 운영물 제거·실기기 수신/PDF/재열람 검증과 명시적 실발송 승인이 남아 있다. 현재 결과를 실제 이메일 소유 인증/실수신 검증 완료로 표시하지 않는다.

## 실행 결과
타입 검사, 전체 단위/통합 359개, Next.js 프로덕션 빌드 통과. 모바일 Chromium/WebKit·데스크톱 Chromium의 기존 앱 E2E 30개 통과. 새 발송 코어는 가짜 공급자 응답으로 검증했으며 실제 SMTP/API/메일함 수신 시험이 아니다. 기본 발송 차단과 복구 보류를 유지한다.


## 공급자 후보 어댑터 추가 (2026-11-15)
Resend HTTP 발송/조회 후보를 추가하고 기존 DB 큐와의 접수→전달 흐름을 가짜 fetch로 검증했다. 실제 계정·DNS·웹훅/worker 등록·실발송은 미구현/비활성이다. 멱등키만으로 조회할 수 없어 ID를 잃은 응답 누락은 운영 검토가 필요하다. [범위·한계·관련 검증](resend-integration.md).
