## 1. 상품 품질·실기기 — 4개

개발자가 준비한 합성 모바일 구매→PDF→복구→관리자 환불 회귀는 통과했다. 브라우저 에뮬레이션을 실제 휴대폰 검사로 세지 않으며, 일반 자동 검사나 개발자의 자체 대조를 독립 전문가 검수로 세지 않는다. 운영자는 기존 본인 운명서의 가독성과 실제 휴대폰 저장을 확인할 수 있다. 토스 계약과 무관한 내용/계산 검수는 주말에도 진행할 수 있다.

## 2. 결제·메일 운영 검증 — 5개

3.1.4 새 도메인 TEST 전체 승인, 3.1.6 토스/카드사 심사·계약/정산, 3.2.4 실제 승인/취소/접근 종료, 4.2.2 메일 운영 조회/웹훅 계정, 4.2.3 실제 OTP·안내 메일 수신/반송.

## 3. 서버 운영·개인정보 — 4개

5.1.4 실제 복구 훈련/외부 경보, 5.2.4 보존/법적 보류/자동 파기, 5.2.5 외부 삭제 이력/최신 원장 복원 보호, 5.3.3 프록시·WAF·운영 제한.

## 작업 방식

새 부가 기능·보고용 별도 커밋·이미 통과한 전체 회귀의 반복을 줄인다. 변경 관련 검사만 수행하고 결과는 기능 변경과 함께 기록한다. 실제 상품/실거래/법적 근거가 필요한 미확인 항목을 숨기거나 완료율을 올리려고 삭제하지 않는다. 토스 회신 전에는 독립적인 상품 검수와 남은 개발을 진행한다. 기존 실제 설정과 데이터를 임의로 변경하지 않는다.
