# 토스 서명 알림 수신 · 기본 비활성 테스트 경로

2026-11-15. 실 Toss 상점 키/보안 키 수신, 실제 PG 호출, 웹훅 등록/외부 공개, 실결제는 수행하지 않았다.

## 동작
`POST /api/toss/webhook`를 추가했다. 기본값은 HTTP 503이며, 일반 고객 콜백/세션과 분리했다. 다음 서버 설정이 모두 맞아야 테스트 수신만 가능하다.

- 기존 `APP_MODE=local`, `EXTERNAL_EFFECTS=disabled` 유지.
- `TOSS_TEST_WEBHOOK_MODE=signed-test-only` 명시.
- API 키는 `test_sk_`만 허용. live 키로는 열리지 않는다.
- 일치하는 테스트 MID와 공급자 발급 64자 hex 보안 키를 별도로 설정. 보안 키와 API 시크릿은 다른 값이다. 브라우저/공개 env/소스에 넣지 않는다.

등록할 테스트 상점과 실제 샌드박스의 보안 키·헤더·서명 값을 대조하기 전에는 운영 호환성 완료로 판단하지 않는다. 보안 키는 제공 형식대로 32바이트로 변환한다. 보안 키 미제공/형식 불일치 시 임의 키나 서명 없는 수신으로 대체하지 않는다.

## 검증 및 상태 변경 경계
1. raw body를 파싱하기 전에 실제 바이트 수 64KiB/전체 읽기 5초 제한. Content-Length 누락·축소에도 적용. 압축 본문과 잘못된 content type 거부.
2. 원문 바이트와 `:` 및 원래 transmission-time 헤더로 HMAC SHA-256 계산. 파싱 후 JSON 재직렬화로 서명하지 않는다. 여러 `v1:` 서명/키 교체 기간을 수용하고, unknown 버전은 처리하지 않는다. 1KiB보다 긴 정상 서명 헤더를 시험했으며 앱 한도는 8KiB다.
3. 서명 비교는 일정 시간 비교를 사용한다. 발송 시각을 기준으로 과거 5분/미래 30초 범위를 적용한다. 이는 앱 정책이며 Toss가 요구한 시간 한도로 표시하지 않는다. 인프라 시계 동기화와 실제 재전송 헤더 확인이 필요하다. 이벤트 `createdAt`이 오래돼도 전송 시각이 새로우면 정상 재전송을 받을 수 있다.
4. 지원 이벤트는 `PAYMENT_STATUS_CHANGED` 한 종류다. 이미 서명이 검증된 다른 제품 이벤트는 처리하지 않고 200으로 응답한다. 현재 가상계좌·빌링·지급대행을 활성화한 것이 아니다.
5. 상점 MID 및 **이미 연결된 주문·결제키**가 모두 맞아야 알림 큐에 넣는다. 알림으로 새 결제 연결을 만들지 않는다. 주문번호는 우리 서비스가 만든 UUID이며, 공급자 식별자/paymentKey/eventId는 임의 접두사 정규식으로 판별하지 않는다.
6. 중복은 본문의 `eventId`를 우선 사용한다. 없는 PAYMENT 이벤트는 고정 순서의 이벤트 시각·주문·결제키·MID·상태·거래키로 식별한다. 전송마다 달라지는 transmission-id/time은 중복 키에 넣지 않는다. 수신 본문 전체나 카드·이메일 필드는 저장하지 않는다.
7. durable 큐 저장 후 200을 반환하고 끝낸다. 수신 중 외부 API를 기다리지 않는다. DB 장애라면 성공 응답하지 않아 공급자 재전송 대상으로 남긴다.
8. **서명된 DONE/금액도 결제 증거로 승인하지 않는다.** 별도 테스트 게이트웨이의 독립 조회를 거쳐 서버 주문금액 33,000원, 키, MID, 통화, 유형, 잔액, 승인 시각을 검증한 기존 코어만 원장을 반영한다. 이후 기존 생성 작업으로 보고서를 제공한다. 과거 이벤트가 늦게 오더라도 현재 결제 상태를 조회한다.

이 엔드포인트의 coordinator gateway는 전송 차단 상태이며 영수증 수신만 한다. 일반 worker에는 실제 Toss 조회를 연결하지 않았다. 키를 환경에 추가해도 실제 결제 승인·자동 조회·유료 AI 보고서 생성이 켜지지 않는다. 실제 테스트 수신도 현재 비활성이다.

## 검증 범위
- Python 표준 라이브러리로 별도 만든 UTF-8 HMAC 기준값 대조, 원문/시간/키 변조, 잘못된 base64, 헤더 누락·과대·복수 서명, 오래되거나 미래인 발송 시각.
- 상점/주문/결제키 불일치, 서명 확인 전 JSON 해석 방지, 지원하지 않는 제품 알림 무시.
- eventId/전문 필드 기준 중복 제거, 전송 시간이 달라지거나 JSON 순서/공백/불필요 필드가 달라져도 동일 이벤트에 중복 처리하지 않음.
- **승인 ACK 누락 → 서명 알림 수신/DB 큐 → 독립 조회 → 서버 원장/생성 작업 복구 → 동일 운명서 재열람**을 가짜 게이트웨이로 통합 검증.
- 올바른 서명/금액을 주장하더라도 조회 증거 금액이 다르면 결제/보고서를 제공하지 않음.
- 느린/큰 본문 중단, 기본 503/live 키 차단, 정상 테스트 수신의 200/비캐시 응답과 외부 fetch 0회.

실제 공급자 payload/키·재전송, HTTPS 등록, 프록시 원문 보존/헤더 한도·시계/WAF, 카드/결제 앱 브라우저 SDK·정상 콜백 및 별도 복구 worker는 추가 검증이 필요하다. 공개 터널/운영 배포를 수행하지 않았다. 모의 성공을 실제 Toss 샌드박스 성공으로 표시하지 않는다.

## 최신 실행 결과
전체 단위/통합 432개, E2E 33개, 타입 검사, 프로덕션 빌드와 standalone/소스/브라우저 비밀값 검사 통과. 실제 Toss 통신은 0회다.
