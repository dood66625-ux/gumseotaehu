# 공개 심사 파일의 버전 확인 — 2026-11-18 KST

`https://gumseo.kr/build-info.json`은 정적 심사 사이트와 같은 산출물로 배포된다. 버전 형식 번호, `public-synthetic-review-assets` 범위, 공개 소스의 40자리 커밋 또는 null만 포함한다. 이메일/호스트명/환경변수/관리자·DB 상태/키는 넣지 않는다. git 작업 트리가 변경됐거나 .git 정보를 확인할 수 없는 로컬 빌드는 커밋을 추측하지 않고 null로 표시한다. CI 커밋 형식과 HEAD 불일치도 거부한다.

기존 Caddy file_server와 assets 복사를 사용하므로 root 소유 서버 설정을 교체할 필요가 없다. HTTP Cache-Control은 no-store다. Next 앱, checkout worker, 모니터 설치 버전이나 DB 최신성을 증명하는 값은 아니며 암호학적 배포 증명도 아니다. 공개 저장소 커밋과 공개 파일의 빌드 표식을 대조하는 용도다.

```sh
npm run review:version
npm run review:version -- --expect <40자리-공개-커밋>
```

조회기는 고정된 공개 HTTPS 주소만 GET하고 리다이렉트/4KiB 초과 응답/올바르지 않은 필드·범위·커밋을 거부한다. 요청은 10초 제한을 사용한다. 정상 확인 0, 버전 null/기대 커밋과 불일치 2, HTTP/통신/형식 등 확인 실패 1이다. 오류 HTTP 상태는 고정 코드로 표시하며 응답 원문은 출력하지 않는다. `privateAppCommitVerified`는 항상 false다. 추가 인증정보나 SSH 키를 요구하지 않는다.

첫 배포 전 조회는 정보 없음으로 실패할 수 있다. 패키지가 발행됐다는 이유만으로 이미 서버에 반영됐다고 표시하지 않는다. 이후 자동 업데이트로 manifest가 배포되면 이 읽기 전용 도구로 공개 정적 파일 버전을 확인한다.

검증: 버전 생성/형식/필드 제한/CI 커밋 불일치와 runtime 패키징 관련 9개, 타입·심사 사이트 빌드·비밀값 검사 통과. 로컬 HTTP JSON 200/no-store/수정 중 소스의 null을 확인했다. 미리보기 서버의 허용 목록에 있으나 실제로 없는 파일 요청도 404를 반환하고 프로세스를 종료하지 않게 수정해 확인했다. 초기 공개 조회는 정보 제공 전 상태였다. 운영 판매/실결제/메일 발송은 변경하지 않았다.
