# 토스 테스트 결제–주문 통합 코어

2026-11-14. 모든 검증은 가짜 게이트웨이/가짜 fetch와 합성 주문만 사용했다. 실제 Toss 호출·키 수신/저장·실결제·개인정보 전송·운영 공개 없음.

## 구현
`lib/integrations/toss-orders.ts`의 TossOrderCoordinator는 기존 DB 주문을 사용하고, 결제 확인 시도를 먼저 저장한 후 게이트웨이를 호출한다. 외부 호출을 DB 트랜잭션 안에서 기다리지 않는다. 앱 라우트/작업자에는 등록하지 않았다.

- 주문 소유권·서버 33,000원·고정 상점 MID·KRW·NORMAL 결제 유형·주문/결제키·잔액·승인 시각을 검증. 은밀한 구독/BILLING 결제를 수용하지 않는다.
- 한 주문의 결제키를 고정하고 다른 주문의 키 재사용을 거부. 결제키는 불투명 식별자로 취급하며 최대 200자 범위로 저장.
- DB lease/세대 번호로 동시 요청과 오래된 응답의 덮어쓰기를 막는다. 중간에 새 알림이 들어오면 후속 조회를 남긴다.
- 승인 응답 누락은 조회로 복구하고 자동 승인 POST는 반복하지 않는다. 재승인이 필요하면 최근 상태 확인에 이어 새 독립 조회가 IN_PROGRESS인 경우만 명시적으로 요청할 수 있다.
- 독립 검증 원장을 저장한 후 앱 처리에 실패해도 기존 worker의 대사가 주문/생성 작업을 복구한다. 재열람 기한은 로컬 복구 시점 대신 검증한 원 승인 시각에서 계산한다.
- 환불은 최근 관리자 인증·원 결제키·서버 총액·전액 취소 완료 기록을 확인한 뒤 반영. 취소 응답 누락도 조회로 복구한다. 단순 응답 성공/웹훅 본문/부분취소를 전액 환불로 표시하지 않는다.
- 취소 재전송은 최근 DONE 독립 조회와 기존 요청 후 14일 이내에 명시적으로만 가능하며, 서버 고정 취소 문구/멱등키를 유지한다. 운영자 검토 사유는 내부에 암호화 보관하고 PG에는 전송하지 않는다. 이는 기술적 재전송 제한이며 고객의 환불권 제한이 아니다. 오래된/모호한 건은 별도 운영 검토 대상이다.
- 앱에 승인 기록을 남기기 전에 이미 전액 취소된 건도 독립 증거로 금융 이력을 대사하고 보고서를 생성하지 않는다.
- 모의 승인/환불 경로가 Toss 연결 주문을 잘못 완료 처리하지 못하도록 구분한다.
- 삭제된 주문의 신규 승인 요청은 거부. 이미 승인 호출이 진행되는 중 삭제가 발생하면 검증된 결제 이력만 기록하고 실패/검토 상태로 보관하며 출생정보/보고서를 다시 만들지 않는다.
- 자동 조회는 backoff와 배치 20건 제한, 연속 실패 8회 후 자동 중단/검토 상태. 명시적 재시도의 최근 조회 시각은 요청 시각과 별도로 기록. HTTP 응답은 256KiB 제한과 시간 제한을 적용. 민감한 공급자 오류 본문/전체 응답/카드 정보를 저장하지 않는다. MID·식별자·상태·시각 등 필요한 증거만 보관하고 환불 사유는 암호화한다. 새 암호화 필드는 DATA_KEY 교체 대상에도 포함했다.
- 관리자에는 테스트 PG 확인 대기/검토와 제공 실패 주문을 집계한다.

## 알림 경계
notify()는 `{orderId,eventId}`의 내부 표준 신호를 받는다. 이미 연결된 주문만 큐에 넣고 본문의 status/amount로 원장을 바꾸지 않는다. 이후 별도 게이트웨이 조회로 확인한다. 이벤트 중복은 주문별 HMAC 식별자로 제거한다. 실제 Toss 웹훅 HTTP 전문 파싱·서명 검증·등록·응답 정책은 아직 구현/연결하지 않았다. 이 메서드를 완성된 웹훅 엔드포인트로 공개하면 안 된다.

## 검증
가격/소유권/상점/통화/유형/결제키/잔액 불일치, 타임아웃·재시작, 동시 승인, lease 교체 후 늦은 응답, 원장 저장 뒤 앱 실패, 전액 취소 응답 누락, 외부 취소, 조작 알림/중복 알림/조회 중 새 알림, 승인 및 취소의 명시적 재시도, 부분취소 거부, backoff, 모의 경로 차단, 키 교체, 삭제와 승인 경합을 시험한다. 실제 HTTP transport+계약 응답 파서+DB 코어도 가짜 fetch로 한 흐름에서 검증한다.

## 미완료
브라우저 SDK와 성공/실패 콜백의 실제 등록, provider worker 배치 등록/조회 순서, 실제 웹훅 어댑터/서명, 실 테스트 상점 MID/테스트 키 연결과 실 샌드박스 반복 검증이 남아 있다. 기본 런타임은 local mock이며 환경에 키만 넣어도 이 코어가 활성화되지 않는다. PG 통합 완료나 판매 가능 상태로 표시하지 않는다.

## 실행 결과
타입 검사, 전체 331개 단위/통합 테스트, Next.js 프로덕션 빌드 통과. 기존 앱 경로의 모바일 Chromium/WebKit·데스크톱 Chromium E2E 30개 통과. 새 Toss 코어의 테스트는 가짜 게이트웨이/fetch이며 실제 브라우저 SDK나 Toss 샌드박스 E2E가 아니다. 실제 전송/활성화는 수행하지 않았다.
