# 토스 심사 보완 — 2026-11-17 KST

운영자가 전달한 보완 요청: 홈페이지 구매 버튼에서 카드 결제창까지 연결, 쉽게 찾을 수 있는 환불·취소 규정, Footer 사업장 주소.

## 확인한 원인과 수정

- 기존 Checkout은 모의 PG만 호출한다. GitHub Pages 미리보기도 브라우저 내부 모의 응답을 사용한다. 실제 SDK를 사용하는 격리 토스 시험 서버에서 승인·취소를 확인한 것과 공개 홈페이지의 버튼 연결은 서로 다른 경로다.
- 정적 미리보기의 `screen=refund`가 일반 안내로 대체돼 상세 환불 규정이 보이지 않았다. 공통 RefundPolicy를 만들어 Next 페이지와 정적 미리보기 양쪽에 연결했다.
- Footer에 주소를 직접 표시하지 않고 별도 사업자 정보 페이지에만 제공하고 있었다. 운영자 제공 주소를 Footer에 추가했다.
- 환불 규정은 제공 전 청약철회, 제공 개시 후 법정 제한 요건, 미제공/오류/중복결제, 계약 불일치, 정정·재열람, 신청 이메일·방법, 법정 환급 기한, 환불 후 접근 종료를 설명한다. 문구는 전자상거래법 제17·18조를 참조했으며 심사 승인이나 법률 검토 완료를 주장하지 않는다.

근거: https://www.law.go.kr/법령/전자상거래법/제17조 및 https://www.law.go.kr/법령/전자상거래법/제18조

## 검증

타입 검사·정적 미리보기 빌드 통과. 390px 모바일 Chromium에서 Footer 주소, 환불 링크의 실제 상세 페이지 이동, 조건/기한/연락 이메일 노출을 확인했다. 합성 데이터만 사용했고 실제 결제·메일 요청은 없었다. 화면 증거는 ignored var/toss-review/refund-mobile.png에 보관한다.

## 미완료

토스에 제출한 정확한 URL 확인을 요청한 상태다. gumseo.kr의 외부 HTTP 확인은 이 실행 환경에서 실패했고, GitHub Pages는 접근됐다. 어느 주소를 심사자가 확인했는지 단정하지 않는다.

실제 결제창 연결은 제출 URL의 호스팅 형태와 서버 엔드포인트에 맞춰 구현·검증해야 한다. 정적 데모 버튼을 실제 결제 연동 완료로 표시하지 않는다. 테스트 결제 경로로 카드사 심사가 가능한지 또는 운영 환경 연결이 필요한지도 토스 요구에 맞춰 확인한다. 실결제 활성화·운영 공개·토스 회신은 수행하지 않았다.
