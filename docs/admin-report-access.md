# 관리자 주문별 열람·오류 확인 · 2026-11-28 KST

주문 목록에 화면 열람 확인/미확인, 최근30일 확인 횟수·첫/마지막 시각(KST), 현재 접근 가능 여부, 작성 실패/보류 코드와 시도 횟수, 웹/PDF/브라우저 오류 및 접근 차단 기록을 추가했다. 환불 완료 후에도 보관기간 내 과거 열람 기록과 현재 접근 종료 상태를 함께 표시한다. 기존 수동 환불·역할·최근 인증 요건은 변경하지 않았다.

기존 `report_open`은 서버 데이터 응답이며 PDF 준비나 다른 서비스 호출도 포함할 수 있고 중복을 기록하지 않는 이벤트다. 이를 실제 열람 횟수로 사용하지 않는다. 새 화면 확인은 고객 운명서가 표시된 뒤 두 번의 animation frame을 지나 전송하는 별도 신호이며 UUID로 중복을 막는다. 다른 주문/미결제/환불/삭제/만료 주문에는 확인 기록을 만들 수 없다. 기록 전송 실패는 읽기를 막지 않는다.

화면 표시 신호는 완독·만족도 증명이 아니다. 기록 없음도 미열람을 확정하지 않는다. 이전 주문은 과거 자료 응답만 남았으면 그 사실만 표시한다. 서버가 알 수 없는 네트워크/브라우저 장애가 있어 오류 기록도 완전한 보장이 아니다. 오류 코드는 고정된 종류/HTTP 상태만 수집하고 본문·질문·생년월일·이메일·IP·오류 원문을 새 기록에 담지 않는다. 관리자 목록 응답에만 요약을 붙이고 일반 고객 주문 목록에는 노출하지 않는다.

`report_access_events`는 주문에 연결된 최소 상태/시각/요청 UUID를 저장하며, 기존 초기화 SQL의 멱등 생성과 인덱스로 적용한다. 기존 정리 작업에서30일 지난 기록을 삭제하고 관리자 조회도30일 범위로 제한한다. 주문이 삭제되면 연결 기록도 삭제된다. 기존 주문/원문/금액을 변경하거나 외부 공급자를 호출하지 않는다.

검증: 단위211건에서 소유권·환불 차단·중복 UUID·예전 응답과 화면 신호의 구분·작성 실패·원문 누락·30일 정리를 통과했다. 아이폰 WebKit/안드로이드/PC Chromium 브라우저24건에서 표시 신호의1회 전송/실패 시 읽기 유지, 관리자 상태 구분, 기존 환불·삭제·만료·기간 종료 접근 차단을 통과했다. 상용 빌드/타입/비밀값 검사 통과. 실제 고객 원문 조회, 실제 결제·환불·AI·메일 호출은 하지 않았다.

배포 확인: 구현 커밋 `05cfcc6`의 [Local verification](https://github.com/dood66625-ux/gumseotaehu/actions/runs/46130070352)과 [runtime build](https://github.com/dood66625-ux/gumseotaehu/actions/runs/46130070354)가 성공했다. 자동 배포 후 실제 도메인의 관리자 번들에서 새 열람·오류 칸과 확인/미확인 문구를, 고객 운명서 번들에서 표시 확인 요청 경로를 확인했다. 공개 상용 접속·접근 차단7개 점검도 통과했다. 실제 관리자 고객 목록·본문·이력은 조회하지 않았으며, 실제 고객 화면 표시 및 환불 판단은 관리자에서 해당 주문을 확인한다.
