# 본 서비스 AI 워커 운영 준비

2026-11-19 KST. 이번 작업은 기본 비활성 운영 코드·관리 명령·복원 보류 연결이다. 실제 서버 등록/유료 호출/고객 데이터 전송/공개 판매 활성화는 하지 않았다. 일반 결제는 여전히 모의 경로이며 비공개 개인 열람 서비스와 예산·DB를 공유하지 않는다.

## 연결된 흐름

일반 worker가 모의 큐와 별개로 `runConfiguredAiCycle`을 순차 실행한다. 모드 미설정/disabled는 호출하지 않으며 알 수 없는 모드는 거부한다. 다음 조건이 모두 맞아야 OpenAI 전송 가능 단계로 들어간다.

- `AI_WORKER_MODE=openai`, `CUSTOMER_AI_APPROVAL=customer-data-approved`라는 별도 운영 설정. 단순 API 키 존재는 활성화가 아니다.
- HTTPS `APP_ORIGIN`, 명시한 `AI_CUTOVER_FILE`, 승인된 정수 USD micros 예산 3개(`AI_DAILY_USD_MICROS`, `AI_LIFETIME_USD_MICROS`, `AI_RESERVATION_USD_MICROS`). 1달러=1,000,000 micros이며 기본 예산을 임의로 정하지 않는다. 1회 예약 최소 60,000 micros와 기존 예산 관계 검사를 유지한다.
- 같은 권위 SQLite DB의 기존 개인정보 체크포인트 source ID, 고정 모델·가격 버전·사이트 origin·예산과 연결된 HMAC 서명 파일, DB에 저장된 동일 전환 시각. 파일은 private 0700 디렉터리의 0600 일반 파일이며 덮어쓰기·심볼릭 링크·다른 키·변조·미래 시각은 거부한다.
- DB의 복원 보류가 0이고 저장된 예산 정책과 일치해야 한다. runtime은 파일/정책을 자동 생성·재등록하거나 보류를 해제하지 않는다.
- 전환 시각 이후 **생성된 주문 중 내부에서 개별적으로 AI 경로로 선택한 주문**만 대상으로 삼는다. 과거 모의 주문 일괄 전환과 신규 주문의 자동 AI 지정은 없다. 실운영 결제/상품 연결은 별도 미완료다.

한 사이클은 1건이다. 작업 선점·주문/버전·결제·만료를 재검사하고 같은 DB에 비용 예약을 커밋한 뒤 기존 고정 Responses 전송기를 호출한다. OpenAI 요청은 이름·이메일·원본 생년월일을 제외한 기존 계약을 유지한다. 자동 네트워크 재시도는 없고 응답 유실/검증 실패는 비용 예약을 남긴다. 이미 예약된 주문/버전은 다시 호출하지 않는다. 생성 후 환불/삭제된 주문은 기존 게시 직전 검사를 유지한다.

## 승인된 운영 전환 때의 관리 명령

아래 명령을 이번 작업에서 실제 서버에 실행하지 않았다. 일반 판매·실고객 개인정보 전송 승인을 받은 운영자가 같은 버전의 웹/worker를 사용하고 모든 worker를 정지한 상태에서 진행하는 절차다. 구버전 worker/DB와 혼용하지 않는다. 운영 관리 명령은 로컬 권한으로만 사용하며 공개 API가 아니다.

1. 실제 DB·origin·예산 3개·키·private 전환 파일 경로를 승인된 환경에 설정한다. 최초 DB source ID는 기존 체크포인트 발행으로 준비한다. API 키나 DATA_KEY를 명령행 인자로 보내거나 출력하지 않는다. `AI_WORKER_MODE`는 disabled로 유지한다.
2. `npm run ai:worker:control -- --enroll --approve-customer-ai`로 최초 정책/서명 파일/DB 등록을 생성한다. 패키지에서는 `node dist/ai-worker-control.js`에 같은 인자를 전달한다. 이 명령은 OpenAI를 호출하지 않고 모드/승인 환경변수를 변경하지 않는다. 재등록은 거절한다.
3. `npm run ai:worker:control -- --status`로 바인딩과 복원 보류·큐 준비 상태를 확인한다. status는 기존 DB를 SQLite 읽기 전용으로 열고 집계만 출력한다. 실제 API 권한·잔액·결과 품질·출시 가능 여부까지 검증하지 않는다. `eligibleCount`는 다음 사이클의 최대 1건 후보 수다.
4. 승인된 전환 이후 주문만 `--select-order <주문 UUID>`로 한 건 지정한다. 결제/유효기간/아직 시작하지 않은 큐를 검사하며 모의 보고서가 이미 생성된 주문은 거부한다. 전환 기준 검사와 경로 지정은 같은 쓰기 트랜잭션이다. 선택 자체는 OpenAI를 호출하지 않는다.
5. 별도 운영 승인 후에만 모드/고객 전송 승인 설정을 적용하고 worker를 시작한다. 웹/worker는 동일한 DB·origin을 사용한다. 첫 통제된 주문의 실제 생성·저장·재열람·PDF·사용량·관리자 보류 표시에 대한 서버 검증은 남아 있다. 실결제/실메일 설정은 별개다.

상태 조회·등록·주문 지정 명령은 공급자 요청 0회다. CLI는 고객 정보·키·주문 ID를 출력하지 않고 제한된 오류 코드만 출력한다. 등록 도중 파일 생성 뒤 DB 커밋이 실패하면 파일을 남긴 채 차단된다. 그 파일을 자동 삭제/덮어써서 계속하지 않으며 운영자가 DB/파일을 대조한다.

## 복원·문제 대응

| 코드/상태                                                | 처리                                                                                                                                                                 |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AI_WORKER_NOT_ENROLLED`                                 | 기존 운영 DB·전환 파일 경로를 확인한다. 복원/원장 소실 여부를 확인하기 전 신규 등록으로 우회하지 않는다.                                                             |
| `AI_CUTOVER_SOURCE_REQUIRED`                             | 같은 DB의 기존 개인정보 체크포인트 source ID를 먼저 준비/확인한다. 다른 DB source를 복사하지 않는다.                                                                 |
| `AI_ENROLLMENT_BINDING_MISMATCH` / `AI_CUTOVER_MISMATCH` | origin·모델/가격·예산·DATA_KEY·DB·파일 일치 여부를 대조한다. 키 교체/정책 변경은 별도 검토이며 자동 재서명하지 않는다.                                               |
| `AI_WORKER_BUDGET_EXHAUSTED`                             | 신규 호출이 중단된다. 보류 비용·사용량을 대조하고 승인 없이 예산/원장을 수정하지 않는다.                                                                             |
| `AI_RESTORE_RECONCILIATION_REQUIRED`                     | 암호화 복원 도구가 DB를 보류한 상태다. worker를 정지한 채 최신 주문·외부 공급자 사용량·삭제 원장·비용 원장을 대조한다. 자동 해제/강제 재호출 명령은 제공하지 않는다. |
| 비용 보류/uncertain                                      | 기존 관리자 AI 보류 목록으로 확인한다. 저장 결과·실제 공급자 사용량 확인 전 재예약/원장 삭제/버전 증가로 재호출하지 않는다.                                          |

종료 신호는 새 작업 시작을 막고 진행 중 호출의 결과/비용 기록을 마무리한다. 공급자 요청은 기존 45초 제한을 유지한다. public health의 외부 효과 요약도 AI/메일 모드가 지정되면 `scoped-opt-in`으로 표시해 모든 외부 효과가 꺼졌다고 오표시하지 않는다. 이 값은 설정 요약이며 발송/생성 성공 증거가 아니다.

공식 암호화 백업 복원 경로는 `ai_worker_enrollment.recovery_hold=1`을 설정한다. 이 상태에서는 모의 생성 선점도 중지하므로 AI 모드를 꺼도 모의 보고서로 우회 생성하지 않는다. 등록 전 백업은 등록 자체가 없어 실행을 차단한다. 이 보호가 임의 파일 복사/과거 DB·서명 파일 동시 롤백이나 다중 서버의 최신성까지 증명하지는 않는다. 외부 최신 원장과 실제 호스트 복구 검증은 출시 진행표 5번에 별도로 남긴다.

## 검증 근거

가짜 키와 모의 HTTP, 실제 SQLite로 등록·전환 시각·과거 큐 제외·성공 저장/재열람·DB 재개방 후 중복 호출 없음·응답 유실 보류·정책/자격증명/복원 보류 차단을 검사했다. 암호화 백업을 실제 복원한 DB에 운영 runner를 연결해 HTTP 0회 차단도 확인한다. 실제 CLI의 개별 지정/반복 지정/읽기 전용 상태 조회는 비용 예약을 만들지 않는다. 서명 파일의 권한/덮어쓰기/변조/DB 바인딩·미래 시각 검사와 패키지 관리 도구 포함도 검사했다.

관련 AI·비용·코어·메일·복원·패키지·상태 점검 테스트 334개, 타입 검사·전체 빌드·비밀값 검사 통과. 실제 API 요청은 0회다.

실제 운영 호스트 설치/고객 전송 승인/통제된 생성·고객 내용 품질 검수/결제 경로 연결은 완료하지 않았다. 진행표 2.2.5는 이 문서에 설명한 **코드 연결·전환·공식 복원 보류 조건** 완료이며 출시 승인이나 전체 서비스 사용 가능 선언이 아니다.
