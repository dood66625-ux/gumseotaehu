## 태후 자문

구매자 이메일로 소유권을 확인한, 결제 완료·열람 가능 AI 운명서에만 질문을 접수한다. 주문당 총 3회이며 질문은 Unicode 코드 포인트 기준 1~50자다. 첫 질문부터 남은 횟수를 (3/3), (2/3) 등으로 표시한다. 원래 보고서가 새 버전으로 바뀌어도 질문 횟수를 초기화하지 않는다.

접수에는 요청 UUID를 사용한다. 같은 요청을 다시 보내도 질문·비용 예약이 하나만 생긴다. 질문 접수와 비용 예약을 같은 SQLite 트랜잭션에 저장하고, 예산이 부족하면 횟수를 차감하지 않고 거절한다. 기존 서명된 일/누적 AI 예산에서 짧은 자문 1건당 USD 0.06를 보수적으로 예약한다. 보고서의 USD 0.50 예약과 기존 전체 한도를 바꾸지 않는다. 이 값은 실제 청구액이 아니며 응답 사용량도 별도로 기록한다.

실제 전송은 등록된 worker가 순차적으로 수행한다. 기존 운명서의 본문과 이전 자문, 새 질문으로 답하고 새 계산을 지어내지 않도록 지시한다. 원본 출생정보·이름·이메일 필드를 자동 첨부하지 않는다. 질문 입력창에 AI 전달과 PDF 기록을 안내하고 개인정보 정책에도 자문 처리를 반영했다.

대기/작성/답변/실패를 구분한다. 응답이 불확실한 호출을 자동으로 다시 보내지 않는다. 이런 실패는 횟수를 보류하므로 운영 확인이 필요하다. 질문과 답변·실패 응답은 암호화하며, 삭제·만료·백업 복원 삭제 명세에 함께 반영한다. 환불·삭제·정정 중 응답이 도착해도 접근 상태와 보고서 버전을 다시 검사해 발행한다.

답변은 운명서 아래에서 다시 읽을 수 있고, 이후 내려받는 PDF에 질문과 답변을 추가한다. 앞서 기기에 내려받은 PDF 파일은 새로 내려받아야 대화가 포함된다. 가상 예시·비공개 체험에서 실제 자문 호출을 만들지 않는다.

## 검증

임시 DB와 모의 응답으로 소유권·50자·3회·중복 접수·재시작·비용 한도·응답 유실·환불 중 응답·PDF 텍스트·삭제 명세를 확인했다. 브라우저 검사는 공급자 호출 없이 수행한다. 실제 AI·메일·결제 호출은 자동 검증에서 실행하지 않는다.

최종 로컬 검증: Vitest 73개 파일·840개 테스트 통과, 타입 검사와 전체 빌드·비밀값 검사 통과. 상세 버튼 대비 7.69:1. Chromium·WebKit에서 390/1440px 운명서 버튼/팝업/50자 제한을 확인하고, 비공개 리더는 320/390/1440px 페이지·저장본·인쇄·삭제 항목 정리를 확인했다. 서버 SSH 22번은 이 환경에서 연결 거부로, 실제 배포는 기존 발행 알림/자동 업데이트 경로를 사용한다. 실제 고객 자문 요청·메일·결제는 검증 중 호출하지 않았다.

첫 발행은 CI에 `pdftotext`가 설치되지 않아 새 PDF 본문 검사에서 중단되었다. 검증 workflow에 poppler-utils 설치를 명시하고, 그 workflow 변경도 runtime 발행을 시작하도록 경로 의존성을 추가했다. 검사를 건너뛰거나 통과로 바꾸지 않는다.

CI 도구 보완 후 원격 검증과 실행 이미지 발행이 통과했다. 발행 알림 스크립트의 실제 결과는 UPDATE_NOTIFY_NOT_INSTALLED로, 즉시 신호 대신 기존 5분 타이머를 통해 반영했다. 이후 자문 암호화 필드를 데이터 키 교체 대상에도 등록하고, nullable 응답 처리와 출생정보 정정 중 대기 질문 정리를 확인했다(관련 216개 테스트 통과). 운명서 접근 오류 화면의 문의 버튼도 제거했다.
