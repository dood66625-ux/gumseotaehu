# 데이터와 보관

| 데이터 | 목적·저장 | 로컬 정리/접근 |
|---|---|---|
| 별명/출생/달력/시각/계산구분/연령 | readings AES-GCM | 미구매 24시간, 구매1년; 본인 세션/이메일 권한 |
| 계산/무료/보고서 | 암호화 불변 payload | 주문 버전/reading_history로 이력; 만료·삭제시 전체 버전 파기 |
| 이메일 원문 | 주문·OTP 암호화 | 원문은 UI/광고 비노출; 검색은 HMAC |
| OTP | HMAC(code+challenge), 암호화 local outbox | 15분·1회·5회 제한; 새 요청시 이전 폐기 |
| 세션 | 무작위 토큰 해시 |2시간, 관리자30분, HttpOnly/SameSite Strict |
| 거래/동의/취소 증빙 | 주문·refunds·감사 원장 | 법정 기록 분리; 기한 파기·법적 보류 구현, 운영 활성화·보존 근거 검토 별도 |
| 문의/답변 | 암호화 payload | 인증된 본인/권한 관리자; 운영 보관정책 확정 필요 |
| 로컬 메일 | AES-GCM outbox |7일; 외부 전송 없음 |
| 이벤트 | event+opaque target |출생/이메일/보고서/광고 외부전송 없음 |

공개 체험판은 가상 정보로 동작한다. 별도 비공개 AI 풀이는 동의 후 OpenAI 전송이 가능하며, 개발 검증에서는 가상 사주 API 호출과 운영자 이메일 수신이 확인되었다. 이를 실제 고객 메일·결제 활성화나 전체 수탁/국외이전 검토 완료로 해석하지 않는다. 정식 운영 전 공급자/국가/목적/근거/보유를 확정해야 한다. AES-GCM 키와 HMAC 비밀은 DB와 다른 안전한 위치에 보관해야 하며 파일 permissions/상용 키관리/암호화 백업/교체·복구는 운영 환경에서 추가 검증한다. 파일시스템·DB 접근은 서버 운영자만 허용한다.

서비스 파기 요청은 인증된 privacy 문의와 주문의 이메일 해시를 대조하고 운영자 감사기록 후 모든 보고서 버전·출생스냅샷을 지운다. 거래원장을 지우지는 않는다. 삭제 뒤 워커가 내용을 재생성하지 않도록 content_deleted를 검사한다. 이미 다운로드한 고객 PDF의 원격 삭제를 주장하지 않는다. 서명된 삭제 이력과 외부 원장 대조를 통한 복원 보호는 구현되어 있다. 외부 저장소 운영 검증과 백업 매체의 실제 파기 주기 확정은 별도 필요하다.
