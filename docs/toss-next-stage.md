# 토스 테스트 연동 준비

## 이번 구현
- 테스트 키만 허용하는 선택형 HTTP transport. 앱/워커에는 아직 연결하지 않음.
- 토스 고정 호스트만 허용, 승인/주문조회/취소 경로 제한, 리다이렉트 차단.
- 서버 가격 22,000원 및 주문/결제키/승인·취소 상태 검증 계약 유지.
- 시간초과/네트워크 오류는 승인 상태 재조회가 필요한 오류로 반환. 자동 결제 재시도 없음.
- 공급자 오류 본문/인증정보를 오류에 노출하지 않음.

외부 호출 없이 가짜 fetch로 승인, 금액 불일치, 조회, 전액 취소, 401/429/500, 잘못된 JSON, 네트워크 실패, 시간초과를 검증했다. 실제 PG 통합 완료를 의미하지 않는다.

## 운영자가 지금 할 일
토스페이먼츠 공식 사이트 https://www.tosspayments.com/ 에서 개발자센터/테스트 환경 이용 가능 여부를 확인한다. 이미 계정이 있으면 새 계정을 만들 필요 없다. 테스트 클라이언트 키·테스트 시크릿 키가 표시되는 단계까지 준비하되 **키를 대화·스크린샷·공개 저장소에 올리지 않는다**. 키 연결은 추후 보안 환경설정으로 진행한다. 실결제 계약·활성화 또는 유료 상품 가입은 이번 단계에서 진행하지 않는다.

## 다음 개발
DB 주문 상태와 승인/조회/취소의 연결 및 장애 복구 코어를 오프라인에서 추가 검증했다. 다음은 브라우저 테스트 SDK, 실제 라우트/워커 등록, 웹훅 신뢰 검증 및 실 샌드박스 검증이다. 현재 체험판은 계속 합성 결제이며, 키만 추가해도 실판매가 활성화되지 않는다.

## 검증 결과
2026-11-14: 타입 검사, 전체 203개 단위/통합 테스트, Next.js 프로덕션 빌드 통과. 실제 토스 네트워크 요청·실결제·실메일·고객정보 외부 전송 없음. 이번 모듈은 런타임 미연결로 기존 브라우저 흐름 변경 없음.

## 비공개 키 연결 절차 (개발 담당자용)
현재 GitHub Pages는 정적 체험판으로 비밀키를 저장하거나 결제 승인 서버를 실행할 수 없다. HTML/JS, GitHub 파일 편집, 채팅으로 시크릿 키를 전달하지 않는다.

비공개 개발 서버/운영 서버를 정한 뒤 담당자가 보안 설정을 안내한다. 로컬 개발에서는 Git 제외된 .env.local에 TOSS_TEST_CLIENT_KEY와 TOSS_TEST_SECRET_KEY를 설정할 수 있다. 저장 파일 권한은 0600을 유지한다. 호스팅에서는 제공자의 비공개 환경변수 기능을 사용한다. NEXT_PUBLIC 접두사는 사용하지 않는다.

`npm run toss:check`는 값 출력이나 네트워크 요청 없이 테스트 키 형식만 검사한다. 실제 키 유효성/가맹점 인증 검증이 아니며 키를 넣어도 앱의 mock 차단은 해제되지 않는다. 저장소 비밀 검사에는 두 변수도 포함된다.

운영자 테스트 키는 2026-11-15 암호화 파일로 수신해 비공개 저장했다. 키 원문은 공개하지 않는다. 개발 서버와 월 예산 결정은 별도로 남아 있다. 서버 비용 승인이나 유료 가입은 별도로 진행한다.

## 주문 통합 코어 보강
TossOrderCoordinator는 DB에 결제 확인 시도·잠금·재조회 일정·알림 중복 제거를 기록하고 검증된 원장을 기존 주문/보고서 작업/환불에 반영한다. 실제 HTTP 계약+응답 파서+DB 연결도 가짜 fetch로 검증했다. 일부러 앱/워커에 실제 transport를 등록하지 않았으며 기본 결제는 여전히 mock이다. 상세 동작·출처·미완료 범위는 toss-order-integration.md를 따른다.

## 결제위젯 테스트 키 선택 (2026-11-15)
운영자가 두 종류의 키가 모두 표시됨을 확인했다. 신규 연동은 주문서형 결제위젯의 같은 상점 테스트 키 `test_gck_` / `test_gsk_` 한 쌍을 사용한다. 형식 검사는 실제 가맹점 일치나 인증 성공을 보장하지 않는다.

위젯 시크릿 키는 주문 ID 조회를 지원하지 않으므로 장애 복구는 DB에 결합된 결제키로 조회한다. 결제키가 없으면 외부 요청 전에 차단한다. 개별 연동 테스트 키의 기존 조회 방식은 유지한다. 공식 기준: https://docs.tosspayments.com/reference/using-api/api-keys.md

`node scripts/toss-key-setup.mjs prepare /absolute/output.html`로 공개키만 포함된 오프라인 입력 파일을 생성한다. 사용자는 Chrome/Edge에서 파일을 열어 테스트 키 두 개와 비공개 저장 동의를 입력한 뒤 암호화 JSON만 전달한다. `node scripts/toss-key-setup.mjs import /absolute/encrypted.json`은 Git 제외·미추적·일반 파일인 `.env.local`만 원자적으로 갱신한다. local/disabled 설정과 다른 키를 보존하며 복호화용 개인키는 사용 후 제거한다. 원문 키는 로그나 대화에 출력하지 않는다.

타입 검사와 455개 테스트 통과. 실제 토스 키 수신·저장, 토스 네트워크 검증, 브라우저 SDK 및 실제 라우트/워커 연결은 아직 완료되지 않았다. 키 저장만으로 외부 호출이나 실결제가 켜지지 않는다.

## 격리된 결제창 시험 추가 (2026-11-15)
[로컬 결제위젯 시험 환경](toss-sandbox.md)을 구현했다. 테스트 키 형식·비공개 저장을 완료했고 실제 토스 SDK/결제수단/약관 렌더링을 확인했다. MID 미설정으로 결제 요청·실제 승인/취소는 차단 중이다. 공개 앱이나 정적 체험판은 모의 결제를 유지한다. 463개 단위/통합 테스트와 공급자를 전부 모의 처리한 모바일/데스크톱 브라우저 계약 테스트를 통과했다. 실제 샌드박스 승인/취소 검증 완료를 의미하지 않는다.
