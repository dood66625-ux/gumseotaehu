# 한 화면 시작 흐름과 미세 모션

메인은 화면 높이 기준으로 시작 버튼·내 운명서 찾기·주요 정책 링크를 배치한다. 상세 소개와 심사용 TEST 결제 진입은 ‘금서 더 살펴보기’를 펼쳤을 때 제공한다. 필수 정보는 삭제하지 않는다. JavaScript가 없어도 기본 이동·상세 펼치기가 동작한다.

태후의 공통 초상은 9초 주기로 1.2~2.6% 확대와 3px 이동을 반복한다. 새 동영상이나 유료 이미지 생성·모델 호출 없이 CSS만 사용한다. 운영자 요청으로 정지 체크박스는 표시하지 않으며 prefers-reduced-motion을 지원하고 인쇄에서는 끈다. 인물의 눈이나 입을 실제로 생성·변형하는 애니메이션은 아니다.

일반 입력은 이름·생일 / 출생시각·대운 구분 / 본인·개인정보 확인의 세 단계다. 이전 값은 DOM에 유지하고 localStorage에는 저장하지 않는다. 다음 단계 전에 현재 필수 입력을 확인하며, 마지막 동의 전에는 계산 API를 요청하지 않는다. 단계 전환은 220ms의 미세한 효과를 쓰며 모션 줄이기에서 끈다. 기존 계산·요금·동의·전송 설정은 유지한다. 비공개 AI reader의 입력 폼과 보고서/PDF 레이아웃은 이번 변경에서 교체하지 않았다.

## 검증

- `npm run test:landing-screen`: 320×568, 375×667, 390×844, 1440×900 메인 화면 넘침 없음, 시작 버튼 노출, 정지 표시 제거/모션 줄이기, JS 비활성 상세 열기 확인.
- 390×844 정적 합성 입력 세 단계의 진행 버튼 노출·뒤로 돌아갔을 때 값 보존 확인.
- 실제 앱의 모바일 모의 구매→보고서/PDF→복구/문의/관리자 환불 흐름 통과. 단계별 검증·동의 없는 요청 방지와 접근성·키보드/JS 비활성 경로도 별도 점검한다.
- 타입·앱/worker/공개 심사 빌드 및 비밀값 검사 통과. 실제 AI·메일·결제를 호출하지 않는다.

작은 창·글자 확대·가상 키보드가 켜진 경우 필요한 스크롤을 강제로 막지 않는다. 긴 보고서·정책 문서의 본문을 화면 높이에 맞춰 자르지 않는다. 실제 iPhone 새 디자인 확인과 Android·결제 앱 복귀 검증을 대체하지 않으며 출시 진행 조건을 추가 완료로 표시하지 않는다.


후속 보정: 입력 검증 화면 높이를 390×664 / 375×667 / 320×568 / 1440×900으로 확대했다. 각 단계의 진행 버튼과 날짜/시각/선택 입력이 fieldset 좌우 경계 안에 있는지 검사한다. 중복 여정 제목을 줄이고 좁은 높이에서 안내·여백을 압축한다. 날짜/시간의 네이티브 최소 너비와 flex/grid 최소 크기를 명시해 프레임 이탈을 막는다. 비공개 reader에도 같은 네이티브 입력 너비 보정을 적용한다. 확대/키보드 상태의 필수 스크롤은 차단하지 않는다.


## 기운의 해석·구매 화면

미리보기는 인사·사주 기둥·오행·각 풀이·각 계산 안내·상품 구성·구매 안내를 개별 화면으로 넘긴다. 모든 내용은 유지하고 화면 간 이동에 API 요청을 추가하지 않는다. 구매는 출생정보/이메일/상품/안내/동의 두 묶음/결제를 분리하며 기존 인증·주문·결제 코어를 유지한다. 필수 동의가 없으면 다음 단계를 막는다. 심사용 가상 주문에서는 고객 동의 입력 화면을 건너뛴다. 결제 결과는 그림과 여백을 줄여 핵심 상태와 열람 버튼을 우선 표시한다. 긴 운명서 본문·법률 문서나 확대/키보드 상태의 필수 스크롤을 숨기지 않는다.

`node scripts/test-reading-screens.mjs`로 390×664·320×568·1440×900의 미리보기와 심사용 구매 각 화면 진행 버튼 위치/가로 넘침을 확인한다. 실제 카드 결제·AI·메일 호출은 하지 않는다. 일반 구매 인증·필수 동의·모의 결제부터 보고서/PDF·환불까지는 실제 앱 E2E로 별도 확인한다.
