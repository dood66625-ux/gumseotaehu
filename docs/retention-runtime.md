# 거래 보존·자동 파기와 외부 삭제 원장

기준일: 2026-11-21 KST. 완료 조건 **5.2.4와 5.2.5의 코드 연결**을 설명한다. 운영의 파기·외부 전송은 비활성이며 실제 고객 DB 삭제, 외부 계정 개설·설정, 운영 환경 변경은 실행하지 않았다. 보존 기간의 법무 검토(6.1.3), 외부 저장소·호스트 복구 인수(5.1.4/6.2.1)는 별도 미완료다.

## 보존과 파기 경로

`lib/retention-runtime.ts`를 기존 worker의 약 30초 유지관리 주기에 연결했다. `RETENTION_ERASURE_MODE` 미설정/disabled이면 DB 조회·파일 열기·외부 요청 없이 반환한다. approved 모드, `RETENTION_ERASURE_APPROVAL=retention-erasure-approved`, 승인된 외부 원장, 소유자 전용 정책 파일이 모두 있어야 실행한다. 설정 예시는 설명용이며 배포기가 자동으로 값을 만들지 않는다.

거래 증빙은 기존 orders/연결 테이블에 보존한다. 기존 운명서·출생정보 콘텐츠 만료와 거래 증빙 보존은 구별한다. 기본 기한은 결제/취소 완료 기준 최소 5년, 종료가 확인된 분쟁은 종료 기준 최소 3년이다. 윤일은 기한을 앞당기지 않는다. 거래 파기는 콘텐츠 만료가 완료된 주문만 대상으로 하며 승인/환불 날짜의 누락·역전·미래, 미완료/오류 환불, 보류, 미종결 문의, 미완료 작업, 메일 잔존, PG/AI 확인 대기를 제외한다. 환불 완료일이 늦으면 그 날짜부터 다시 5년을 센다.

한 번에 주문 최대 100개·분쟁 최대 100개다. 순회 커서를 보존해 오래된 보류 주문만 반복하며 뒤의 후보를 굶기지 않는다. 새 FK 의존 테이블은 검토 없이 지우지 않고 전체 배치를 롤백한다. 공유 readings는 다른 주문/이력이 참조하면 남긴다. 거래의 보고서·작업·환불·메일 변경·PG 기록·사용량·과거 readings·연결 감사 기록 등을 함께 제거한다. 누적 AI 예산 원장의 금액·불투명 식별자는 재실행에 따른 예산 초기화를 막기 위해 유지한다. 파기 영수증에는 연락처·생년월일·본문 없이 UUID·범위·시각만 둔다.

SQLite secure_delete와 완료 후 WAL truncate를 적용한다. WAL 독자가 정리를 막으면 완료로 확정하지 않고 재시도를 요구한다. 매체 전체의 물리 소거, 스냅샷/공급자 백업 매체 삭제를 보장하는 기능은 아니다. 오래된 암호화 백업은 아래의 최신 삭제 이력을 적용해야 복원할 수 있다.

## 보류 검토와 실행 승인

작업 트리 밖 일반 파일, 단일 링크, 0600 등 소유자 전용 권한, root/실행 계정 소유를 요구한다. 심볼릭 링크·작업 트리 내부·1MiB 초과·24시간을 넘은 검토는 거절한다. 운영자가 모든 보류와 분쟁 종료를 확인한 후 파일을 갱신해야 하며, 검토를 생략하면 파기가 멈추는 설계다. 공개 HTTP 파기/보류 해제 API는 제공하지 않는다. 권한은 운영 계정의 파일 접근으로 제한한다.

필수 JSON 필드는 다음과 같다. 예시 UUID는 가상 값이며 실제 sourceId는 현재 DB의 privacy_checkpoint_source와 일치해야 한다.

```json
{
  "version": 1,
  "purpose": "approved-retention-erasure",
  "sourceId": "11111111-1111-4111-8111-111111111111",
  "reviewedAt": 1790000000000,
  "holdsReviewed": true,
  "transactionYears": 5,
  "disputeYears": 3,
  "heldOrders": [],
  "heldDisputes": [],
  "closedDisputes": []
}
```

`closedDisputes` 각 항목은 `{id: ticket UUID, closedAt: 실제 종료 시각ms}`다. 기존 ticket의 created를 종료일로 간주하지 않는다. status도 closed/resolved여야 한다. 보류 추가·해제는 새 reviewedAt의 정책으로 명시하며 DB에는 검토 시각·정책 해시·적용 시각을 감사 기록으로 보존한다. 같은 검토 시각의 내용을 몰래 바꾸거나 이전 검토로 되돌리는 것은 거절한다. 종료일/보류 목록은 운영자의 확인 책임이며 도구가 법적 사실을 추정하지 않는다.

`RETENTION_ERASURE_POLICY`가 이 파일을 가리킨다. 실제 운영 승인 전에는 파일과 활성화 환경 변수를 만들지 않는다. 이전 `retention:plan`은 읽기 전용 사전 집계로 유지하고, 분리 vault staging 도구는 이관 실험용으로 남긴다. 불완전한 별도 vault를 자동 파기 기준으로 신뢰하지 않는다.

## 외부 원장 프로토콜

`lib/external-deletion-ledger.ts`는 HTTPS 고정 URL에 GET/조건부 PUT을 수행한다. 외부 서버는 강한 ETag와 If-Match/If-None-Match의 원자적 비교·교환, 인증, 읽기 후 쓰기의 일관성을 제공해야 한다. 리디렉션은 거절한다. 최대 응답 크기·10초 요청 제한을 두며 공급자 응답/자격증명을 로그에 내보내지 않는다.

설정은 `PRIVACY_EXTERNAL_LEDGER_MODE=conditional-https`, `PRIVACY_EXTERNAL_LEDGER_APPROVAL=encrypted-deletion-ledger-approved`, 전용 HTTPS URL과 별도 접근 토큰이다. 기본은 disabled다. 전송 본문은 현재 DATA_KEY로 AES-256-GCM 암호화한 객체이며 원장에는 DB UUID, 생성 시각, 최소 삭제 ID/시각/범위, pending 상태만 들어간다. 외부 저장소의 이전 버전/불변 보존·권한 분리·장애 경보와 키 복구는 계정 선택 후 현장 인수에서 확인해야 한다. DATA_KEY 교체 시 외부 원장도 승인된 유지보수 절차로 교체해야 하며 자동으로 새 키로 덮어쓰지 않는다.

이전 UUID, 삭제 목록 누락, 전체 삭제를 콘텐츠 삭제로 낮추는 변경, 시각 역행, 잘못된 ETag/암호문, 실패한 읽기/쓰기/읽기 확인은 거절한다. worker와 runtime-backup이 로컬 체크포인트를 동기화한다. 오류 시 privacy checkpoint health를 실패로 표시한다. 실제 외부 저장소를 검증했다는 offsiteVerified 플래그는 올리지 않는다.

## 장애와 복원 보호

1. DB 쓰기 트랜잭션에서 후보와 보류를 다시 검사한다.
2. 삭제 예정 전체 목록을 외부에 pending=true로 저장하고 읽어 확인한다. 실패하면 원본을 지우지 않는다.
3. 원본·자식 데이터와 삭제 영수증을 한 트랜잭션으로 반영한다.
4. DB 커밋·WAL 정리가 끝나면 동일 목록을 pending=false로 외부에 확정한다.

2 이후 DB 실패/프로세스 중단이면 원장은 pending으로 남아 복원을 차단한다. DB 커밋이 완료됐다면 다음 worker의 같은 로컬 목록으로 확정할 수 있다. DB가 롤백되어 목록이 다르면 자동으로 외부 목록을 지우거나 되돌리지 않으며 조사해야 한다. 타임아웃을 성공으로 간주하지 않는다.

공식 restore CLI는 외부 모드에서 서명 체크포인트를 요구한다. 로컬 목록과 최신 외부 목록이 다르거나 24시간 초과·다른 DB·pending·통신 장애면 거절한다. 구형 --deletions 경로와 직접 라이브러리 호출로 이 검사를 건너뛸 수 없다. 복원은 임시 오프라인 파일에서 삭제 이력과 인증/발송/생성 보류를 적용하고 외부 원장을 다시 확인한 후 새 목적 파일로 게시한다. 대상/운영 DB는 덮어쓰지 않고 서버도 시작하지 않는다. 기존 키 백업의 복원·DATA_KEY 교체에도 같은 원장을 적용한다.

검사 후 다른 서버에서 삭제가 추가될 수 있으므로 이 파일을 곧바로 운영 활성화해서는 안 된다. 호스트 인수 시 쓰기 중지·최신 원장 재대조·보류 목록 대조를 수행해야 한다. 이 구현은 분산 서버 전체에 대한 활성화 잠금이나 외부 매체의 물리 소거를 주장하지 않는다.

## 검증 근거

`tests/retention-runtime.test.ts`는 실제 스키마의 가상 SQLite에서 기본 비활성, 정책 출처/최신성, 감사/보류 정책 역행, 5년/3년 만료, 보호 대상 제외, 의존 FK 실패·원본 롤백, 외부 장애·미확정 barrier를 확인한다. 파기 전 암호화 백업을 새 오프라인 DB로 복원하고 키까지 교체해 주문/문의가 되살아나지 않는 것을 확인했다.

`tests/external-deletion-ledger.test.ts`는 가상 외부 전송으로 암호화·조건부 저장·최신성/출처/역행·pending/불통 차단과 복원 도중 새 삭제 발생을 검증한다. 실제 고객 데이터나 운영 외부 저장소를 사용한 결과가 아니다.
