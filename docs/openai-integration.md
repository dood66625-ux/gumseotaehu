# OpenAI 해석 엔진 · 합성 검증 경로

2026-11-15 기준. **고객용 AI 서비스 활성화 완료가 아니다.**

## 구현
- Responses API `/v1/responses`, strict JSON schema, `store:false`, 9,000 출력 토큰 제한. 모델은 검증용 `gpt-5.4-mini-2026-03-17`로 고정했다. 운영 모델/가격 확정은 별도다.
- `buildAiRequest`는 계산된 명리 근거만 전달한다. 이름·이메일·원본 생년월일은 요청에 포함하지 않는다. 계산 결과도 실제 고객과 연결되면 개인정보일 수 있으므로, 이를 익명화 또는 국외이전 승인 대체로 취급하지 않는다.
- 실제 HTTP 전송은 고정된 합성 `known`/`unknown` 두 계산 결과와 요청 전체가 일치할 때만 가능하다. 요청 경로·메서드·헤더·모델·본문 변조 거부. 앱 라우트·일반 worker·공개 체험판에는 등록하지 않았다.
- 고정 API 호스트, 리다이렉트 거부, 45초 중단, 응답 스트리밍 256KiB 제한, 민감한 공급자 오류 문구 비저장. HTTP 401/403/429/5xx, 불완전 응답·거절·비정상 JSON·사용량 이상·형식/근거/명시적 금칙 표현을 거부한다.
- `429`의 `insufficient_quota`/`billing_hard_limit_reached`와 `rate_limit_exceeded`를 구별하며, 코드를 주지 않으면 추측하지 않는다. 네트워크 결과 미확정과 시간 초과를 별도 처리한다. HTTP 어댑터의 자동 재호출은 없다.
- 합성 테스트는 별도 `var/ai-synthetic/journey.sqlite`에서 모의 결제→비동기 생성→암호화 저장→동일 원문 재열람→PDF 경로를 실행한다. 실제 결제·메일·고객정보 전송은 수행하지 않는다.
- 비동기 작업은 DB 트랜잭션 밖에서 생성하고, 저장 직전 작업 임대/시도 번호·주문 결제/정정 버전·삭제·만료를 다시 확인한다. 만료된 이전 작업자는 새 작업자의 결과를 덮어쓸 수 없다. 정상 라우트와 worker는 규칙 mock을 유지한다.
- 보고서와 같은 트랜잭션으로 토큰/추정 비용 인덱스를 저장하고, 관리자 화면에서 저장 원문 기준 사용량·USD 추정치·추정 미확인·집계 대기 건수를 조회한다. 실패/미응답 호출과 별도 합성 테스트 비용은 이 집계에서 제외됨을 표시한다. 실제 청구액을 0원으로 고정 표시하지 않는다.
- 저장 보고서에 AI 프롬프트 버전·선택 모델·가격 기준 버전·토큰 사용량·USD 추정치를 보존할 수 있다. 임의 환율로 원화 실비를 만들지 않는다. 웹/PDF의 AI 표시도 저장된 provider에 따른다.

## 호출 제한과 비용
`var/ai-synthetic/budget.sqlite`에 전송 전에 예약한다. **기본 전체 수명 3회**, 각 회 USD 0.06 보수적 추정 예약, 기본 합계 USD 0.18 예약이다. 2026-11-18 사용자의 충전 완료 및 계속 진행 지시에 따라 `funded-resume-v1` 1회(USD 0.06)를 기존 원장에 별도 기록했다. 현재 총 4회/예약 USD 0.24이며 `--funded-resume`를 반복해도 더 늘어나지 않는다. 기존 실패/사용량/호출 행은 보존했다. 실패·미확정·프로세스 종료에도 예약을 돌려주지 않는다. 별도 프로세스의 동시 예약도 SQLite 트랜잭션으로 제한한다. 이 파일을 삭제해 반복 호출하지 않는다.

이 금액은 현재 공개 단가를 이용한 앱의 계산이며 OpenAI 청구서나 플랫폼 결제의 강제 상한 보증이 아니다. 모델 단가/세금/계정 정책이 바뀔 수 있다. 실제 청구 비용은 공급자 대시보드에서 확인해야 한다. 사용량이 반환되지 않은 시도는 비용 0으로 확정하지 않는다. 이 테스트 제한은 운영 고객의 전역/일별/주문별 사용 한도를 대신하지 않는다.

참고: [모델·단가·지원 기능](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create). API 보관 정책/국외이전 검토는 `store:false`만으로 완료되지 않는다.

## 실제 수행 결과
- 운영자 제공 키를 비공개 `.env.local`에 저장했고, 모델 목록 인증 요청 HTTP 200을 확인했다. 폐기된 이전 키를 재사용하지 않았다.
- `npm run ai:synthetic -- --live known` **1회** 요청: HTTP **429** (`AI_QUOTA_OR_RATE_LIMIT`). 이 최초 응답은 숫자 상태만 확인한 버전이므로, 잔액 부족/프로젝트 지출 제한/일시적 호출 제한 중 무엇인지 확정하지 않는다. 이후 원문을 노출하지 않는 코드 분류를 보강했다.
- 추가 실제 호출은 중단했다. 알려진 사용량 없음. 합성 주문은 `retrying`, 보고서는 미생성이다. 실제 AI 작성 성공·실 AI PDF·실 AI 품질 또는 재열람 검증을 통과했다고 주장하지 않는다.
- 단위/통합 402개 통과. 전체 E2E 30개와 배포 묶음 보강 후 모바일 주요 여정 2개 추가 통과.
- 성공 응답의 해석/저장/재열람·실패/기한/환불/정정/중복 경합은 가짜 HTTP 응답과 주입 생성기로 검증했다. 이는 실 API 성공 검증과 구별한다.

## 한도 확인 후 재개
OpenAI [결제/잔액](https://platform.openai.com/settings/organization/billing), [조직 한도](https://platform.openai.com/settings/organization/limits), 프로젝트 `ysh`의 사용량/예산/모델 권한을 확인한다. ChatGPT 구독과 API 결제는 별개다. 새 키를 다시 만들 필요가 있다고 단정하지 않는다. 보안 키·잔액 화면 캡처를 대화에 보내지 않는다.

승인된 테스트를 명시적으로 다시 실행할 때만:

```sh
npm run ai:synthetic -- --live known
# 성공 후 동일 명령 재실행은 저장 원문을 재사용하고 API 호출 0회를 확인한다.
# 다음 고정 예시(현재 잔여 슬롯이 있을 때만; 한도 원장은 자동 초기화하지 않음):
npm run ai:synthetic -- --live unknown
```

Node 24의 환경 프록시를 사용한다. 명령은 사용자 출생정보·이메일·임의 프롬프트·모델·외부 URL을 인자로 받지 않는다. 성공 증거/PDF는 ignored `var/ai-synthetic/`에만 남긴다. CI는 이 명령을 실행하지 않고 가짜 transport 테스트만 수행한다.

## 출시 전 남은 일
실제 성공 보고서의 명리 전문가/문체/개인화 검수, 무료 첫 반응/무료풀이/구매 연결 대사의 AI 설계·저장/개인정보 검토, 운영 모델·한도·비용 기준, 운영 전역 비용 원장·지속 재시도/미확정 비용 대사, 고객 데이터 전송 승인/고지, 실제 worker 연결이 필요하다. Toss/메일/호스팅/법률/실기기 검증과 공개 배포 승인도 계속 차단되어 있다.

## 배포 묶음의 비밀값 보호
로컬 빌드의 standalone 폴더에서 `.env.local` 사본이 발견됐다. 해당 경로는 ignored 상태였고 외부 배포하지 않았다. Next tracing에서 `.env*`/`var`를 제외하고 `postbuild`에서 env/데이터 사본을 제거한다. 시작 명령은 정리되지 않은 폴더 또는 symlink 루트를 거부한다. 비밀값 검사는 소스·브라우저 파일뿐 아니라 standalone 서버 묶음까지 검사한다. 실제 비공개 설정이 없는 빌드로 모바일 구매/PDF/재열람을 다시 검증했다. 런타임 비밀값은 배포 묶음 대신 승인된 환경으로 주입해야 한다.

## 충전 후 실제 검증 (2026-11-18 KST, 이전 실패 기록보다 최신)

- 사용자가 충전 완료와 재개를 지시해 승인된 기존 키를 재사용했다. 새 키 생성/키 값 출력은 없다.
- known 실제 생성·9개 장 암호화 저장·동일 원문 재열람·PDF 성공. 단, 본문 233~302자로 목표보다 짧아 판매용 품질 통과로 처리하지 않는다. 이 v1 원문은 보존한다.
- v2는 새 AI 응답의 장당 최소 350자를 schema/검사로 요구하고 금칙 표현을 부정문에서도 반복하지 않도록 지시한다. 한 unknown 응답은 안전 검사에서 거부돼 저장되지 않았다. 당시 원문을 보관하지 않아 정확한 거부 구절은 확인하지 못했다. 이후 고정 합성 응답은 DATA_KEY로 암호화한 private 증거에 보관하도록 보강했다.
- 1회 funded-resume로 unknown v2 생성 성공: 9개 장 355~448자, 원본 계산 근거/주의문·시간 미상 시주/대운 제외·12개월 안내 보존. 안전 검사 기준을 완화하지 않았다. 기본 검수를 통과한 것이며 전문 명리·문체/상품성 검수 완료는 아니다.
- 저장된 unknown 원문 재열람은 실제 API 호출 0회. 모바일 Chromium에서는 원본 합성 DB의 폐기 가능한 복사본을 사용해 정상 이메일 인증→같은 저장 원문→가시적인 AI 표시→PDF 다운로드를 확인했고 모델 호출은 0회였다. 원본 DB/예산 원장의 통제 값을 지우지 않았다.
- 이번 충전 후 3회 응답의 알려진 사용량 기준 추정 합계 USD 0.035572. 저장 보고서 2개와 거부 응답 1개를 포함한다. 예전 429 시도 1개는 사용량 미확인으로 유지한다. 원장 총 4회, 기존 기본 3회 + 1회 추가만 기록했으며 더 호출하지 않았다. 추정 단가이지 실제 청구서 확인이 아니다.
- 실제 AI PDF는 12쪽, 한글 추출과 본문 페이지 시각 확인을 수행했다. 파일은 ignored `var/ai-synthetic/unknown-report.pdf`, 모바일 다운로드는 `unknown-browser-report.pdf`에 있다. 민감한 원문/암호화 DB/키/응답은 공개 저장소에 올리지 않는다.

관련 오프라인 계약/HTTP/예산/비동기 저장/준비도 테스트 51개와 타입·빌드·비밀값 검사가 통과했다. 실제 AI worker 등록·일반 입력의 v2 실검증·전역/일별 비용 통제·고객정보 전송 조건과 전문/운영 검수는 남아 있다. 고객용 생성은 아직 규칙 mock이며 이 시험 성공만으로 실판매 AI가 활성화되지 않는다. [비식별 검증 요약](openai-funded-test-results.json).

모델 호출 없는 재열람 UI 확인 도구: 빌드 후 `node scripts/test-stored-ai-report.mjs`. 원본 합성 DB를 읽기 전용으로 열어 폐기 가능한 복사본을 만든다. 인증 시험용 제한 창은 복사본에서만 초기화하고 원본/예산은 건드리지 않는다. 이 도구는 기존 unknown-evidence의 reportId로 실제 orderId를 조회해 올바른 URL을 사용한다. 보고서/주문 ID를 혼동하지 않도록 생성 증거에도 둘을 구분한다.
