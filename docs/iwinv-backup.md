# iwinv 테스트 환경 백업

현재 단계는 합성 데이터 전용이다. 운영용 자동 배포·외부 백업 스케줄은 아직 설치하지 않았다.

`scripts/runtime-backup.ts`는 `dist/runtime-backup.js`로 번들된다. 새 이미지에 포함된 후 다음 명령으로 실행한다. 기존 7abef04 이미지에는 이 도구가 없으므로 먼저 새 이미지를 전달해야 한다.

```bash
sudo docker compose --env-file /etc/gumseo/test.env -f /opt/gumseo/compose.local.yml exec -T worker node dist/runtime-backup.js
```

이 명령은 DB와 같은 데이터 볼륨의 backups 폴더에 AES-256-GCM 암호화 백업을 생성하고, 최신 서명된 삭제 체크포인트와 함께 별도 임시 파일로 복원·무결성 검증한다. 실제 DB는 교체하지 않는다. 임시 복원 파일은 성공·실패 모두 정리한다. 백업 경로와 체크포인트 경로만 출력하고 비밀값은 출력하지 않는다. 원격 전송은 수행하지 않는다.

서버 외부 복사에는 아카이브뿐 아니라 최신 삭제 체크포인트와 서명된 freshness receipt가 필요하다. 암호화 키는 백업과 분리해서 보관해야 한다. 오래된 체크포인트로 실제 복원하면 안 된다. 같은 서버에만 저장된 백업은 서버 손실을 대비하는 외부 백업이 아니다. 운영 단계의 삭제·보관 정책, 정기 외부 업로드, 최신 체크포인트의 권위 있는 보관과 복구 훈련은 별도 완료 조건이다.

반복 배포는 먼저 검증된 이미지·커밋·해시를 고정하고, 배포 직전 백업과 복원 시험이 성공한 뒤 진행한다. `docker compose down -v`를 실행하거나 새 비밀값으로 기존 키 파일을 덮어쓰지 않는다. 코드 롤백은 DB 스키마 롤백을 의미하지 않는다. 무인 운영 배포는 아직 활성화하지 않는다.
