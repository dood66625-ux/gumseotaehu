# 문의·결제 상태 장애 복구 보강 — 2026-11-18 KST

## 수정

- 문의/환불 화면은 목록 조회의 401만 재인증 대상으로 처리한다. 일시적인 조회 장애는 조회 오류와 재시도 버튼으로 보여주며, 구매/문의 내역이 없거나 로그아웃됐다고 표시하지 않는다.
- 문의 POST 성공 시 표시한 접수번호는 후속 목록 조회가 실패해도 유지한다. `주문·문의 내역 다시 확인`은 GET 조회만 수행하며 같은 문의를 다시 POST하지 않는다. 접수 실패 오류와 목록 조회 오류는 별도 상태다.
- 결제 상태 조회는 응답이 끝난 뒤 2초 후 다음 조회를 예약한다. 느린 응답 위에 새 요청이 쌓이거나 이전 응답이 최신 응답을 덮는 일을 막는다. 화면 이동 후 재예약하지 않는다.
- 고객 화면의 worker 실행 명령은 추가 결제 없이 주문번호로 복구·환불을 요청하는 안내로 바꿨다.

## 검증

모바일/PC Chromium에서 문의 일시 장애→재조회, 접수번호 보존→재조회 시 POST 1회 유지, 세션 만료 시 재인증, 결제 상태 응답을 10초 보류하는 동안 중복 GET 없음→정상 상태 회복을 검사했다(8개). Next.js 빌드·타입·비밀값 검사도 통과했다. 처음 테스트 실행의 실패 4개는 Next.js 경로 안내용 별도 alert까지 선택하는 테스트 locator 문제였으며, 앱 경고 문구로 대상을 좁힌 뒤 해당 4개 모두 통과했다.

실제 로컬 SQLite/모의 결제/worker/PDF/이메일 재인증/문의/관리자 전액 mock 환불 경로의 기존 모바일 통합 시나리오도 통과했다(1개, 합계 9개). 이전 관리자 UI 변경 이후 남아 있던 오래된 환불 버튼/상태 locator도 현재의 명시적 모의 전액 환불 버튼과 완료 메시지에 맞춰 수정한 뒤 재검증했다. 공급자 API 요청이나 실제 카드 승인/메일 발송은 하지 않는다.

## 범위와 한계

접수 POST의 응답 자체를 잃는 상황에 대한 서버 멱등 접수 기능을 추가한 것은 아니다. 이번 변경은 성공 응답을 받은 접수가 목록 조회 장애 때문에 사라져 재접수하게 되는 문제를 해결한다. 실제 수신함, 업체 반송/운영 연결, iOS/Android 실기기·결제 앱 복귀 검증은 남아 있다. 정확한 iwinv 배포 커밋은 별도 확인하며 GitHub 패키지 발행만으로 서버 적용을 완료 처리하지 않는다.

출시 준비도 약 73%, 이메일 보강 약 90%, 토스 보완 약 95%를 유지한다.

## 공통 브라우저 요청 제한 — 2026-11-18 KST

`lib/client-api.ts`로 전송 코드를 분리했다. 세션 준비부터 실제 요청·응답 JSON 읽기까지 합산 20초 제한을 적용한다. AbortSignal을 전달하고, 전송기가 취소를 무시하더라도 화면은 제한 시간에 대기에서 벗어난다. 늦게 도착한 세션 준비 응답이 제한 시간 이후 결제/문의 POST를 시작하지 못하도록 차단한다. 세션 준비가 HTTP 오류나 잘못된 응답으로 실패하면 실제 변경 요청도 실행하지 않는다.

시간 초과나 연결 유실을 서버 취소/접수 실패/결제 실패로 단정하지 않는다. 변경 요청은 결과 불명확과 내역 확인 안내를 표시하며 이 전송 계층에서 자동 재시도하지 않는다. 기존 결제 상태 화면의 읽기 전용 GET 폴링은 별도다. 오류 응답이 HTML 등 JSON이 아니어도 HTTP 401은 보존하고, 파싱 오류 원문이나 HTML 본문을 화면에 노출하지 않는다.

구매 화면의 인증 상태 조회 실패도 처리하며, 출생정보 조회 오류에는 GET 재조회 버튼을 제공한다. 이 버튼은 주문 생성이나 결제를 수행하지 않는다. 문의 POST의 결과를 잃었을 때 입력 내용은 유지한다. 사용자가 직접 재접수하기 전에 내역을 확인해야 하며 서버 접수 멱등 기능이나 공급자 대사를 추가한 것은 아니다.

검증: 전송 단위 7개(무응답/응답 본문 지연/세션 실패/늦은 세션 응답/POST 응답 유실/비JSON 401/정상 처리), 모바일·PC 네트워크 E2E 6개, 기존 이메일 E2E 4개, 로컬 구매/PDF/재인증/문의/mock 환불 E2E 1개 통과. 정적 합성 체험판 전체 흐름도 통과했으며 외부 API 요청은 0건이다. 빌드·타입·비밀값 검사 통과. 실제 결제·메일·유료 AI 호출 및 고객정보 외부 전송은 수행하지 않았다.

## 오래된 조회 응답 차단 — 2026-11-18 KST

공통 조회 hook은 요청 세대와 조회 경로를 함께 추적한다. 대상이 바뀌는 렌더부터 이전 경로의 데이터/오류를 숨기고, 최신 요청의 성공/실패만 화면 상태에 반영한다. 같은 경로를 수동 재조회해도 늦은 이전 요청이 결과를 덮지 못하며, effect 정리 시 진행 중 응답의 상태 반영을 무효화한다. 서버 요청의 원격 취소나 데이터 삭제를 의미하지 않는다. 기존 20초 요청 제한·POST 자동 재전송 금지도 유지한다.

실제 hook을 브라우저용 시험 fixture에 번들해 모바일/PC에서 이전 경로의 늦은 성공, 새 요청 중 이전 내용 숨김, 이전 실패가 새 성공 덮기, 이전 성공이 현재 오류 지우기를 검증했다(8개). fixture URL은 테스트의 네트워크 가로채기로만 존재하며 앱 라우트나 배포 패키지에 추가하지 않는다. 빌드된 Next 앱에서는 구매 출생정보 재조회 2개와 실제 로컬 구매/PDF/재인증/문의/mock 환불 통합 1개도 통과했다. 합계 E2E 11개, 타입·프로덕션 빌드·비밀값 검사 통과. 실제 메일/카드 승인/유료 AI 호출은 없다.

## PDF 전송 복구 — 2026-11-18 KST

`lib/report-download.ts`가 PDF 응답 본문까지 합산 20초 제한을 적용한다. AbortSignal과 reader 취소를 사용하고 자동 재다운로드하지 않는다. 최대 20MiB를 스트림 누적 중 검사하며 PDF MIME/비어 있지 않은 본문/%PDF- 시작 표시를 확인한다. 이는 PDF 전체 구조/내용의 전문 검증이 아니다. HTML 오류 페이지·빈 응답·과대 응답을 다운로드 파일로 전달하지 않고, 오류 원문은 표시하지 않는다. HTTP 401에는 재인증을 안내한다.

다운로드를 시작할 때 이전 완료 안내를 지우고 중복 클릭을 막는다. 성공 문구는 브라우저 다운로드 요청을 의미하며 파일 저장 완료/고객 열람을 증명하지 않는다. 저장 여부는 브라우저 다운로드 목록에서 확인하도록 안내한다. 결제·메일·구매 기록을 변경하지 않는다.

검증: 단위 6개(PDF 본문, MIME/빈 본문, PDF로 위장한 HTML, Content-Length 없는 과대 스트림, 응답 본문 무응답, 비공개 오류 원문 비노출), 모바일/PC PDF 장애 복구 4개, 실제 로컬 구매/PDF/재인증/문의/mock 환불 통합 1개, 타입·프로덕션 빌드·비밀값 검사 통과. 고객 기기의 실제 저장 완료나 iOS 실기기 검증은 별도다.

## 관리자 처리 후 조회 복구 — 2026-11-18 KST

선택 주문 업무가 성공 응답을 받은 뒤 관리자 개요 조회만 실패해도 처리 완료 안내를 유지한다. 일시 장애는 인증 만료로 취급하지 않고 GET 재조회만 제공하며, 장애 화면에서는 업무 실행 폼을 숨긴다. 잘못된 주문 검색 조건도 해당 화면에서 수정한 뒤 조회할 수 있다. 읽기 요청 세대 검사로 과거 응답의 화면 복원을 막고, 초기 조회 중 인증 화면이 먼저 나타나지 않게 했다.

401/403은 보호된 화면 데이터/선택 주문/기존 안내를 비우고 재인증으로 전환한다. 명시적인 화면 인증 갱신·로그아웃 성공·관리자 세션 종료 성공 시에도 화면을 비운다. 화면 데이터 제거 자체가 서버 세션 삭제나 로그아웃 완료를 의미하는 것은 아니다. POST 응답 유실은 기존 공통 API의 결과 불명확 안내를 유지하며 이번 변경을 서버 멱등 처리나 실제 토스 환불 연결이라고 표시하지 않는다.

검증: 모바일/PC의 개요 장애→조회 복구, mock 환불 성공→조회 실패→GET 재조회 시 업무 POST 1회 유지, 권한 만료 시 보호 데이터 제거, 잘못된 검색 조건 수정 8개 통과. 실제 로컬 구매/PDF/재인증/문의/관리자 MFA/mock 전액 환불 통합 1개와 빌드·타입·비밀값 검사도 통과했다. 실제 결제/취소·메일 발송·고객정보 외부 전송은 수행하지 않았다.

## 환불·삭제·열람기한 표시 — 2026-11-18 KST

공통 `customerOrderState`로 결제 확인 대기/작성 중/복구 필요/취소 확인 중/전액 취소/원문 삭제/기한 종료/열람 가능/확인 필요를 구분한다. 오래된 fulfillment=ready만으로 열람 가능이라고 표시하지 않는다. 유효한 paid/ready와 미래 열람기한이 모두 있어야 열람 링크를 제공한다. 취소·삭제·기한 종료·유효한 기한 정보 누락에는 이메일 변경/열람을 노출하지 않는다. 서버의 소유권·결제·기한 검사가 최종 권한이며 UI 판단으로 이를 대체하지 않는다.

종료된 주문은 작성 중이라는 문구와 자동 폴링을 멈추고, 수동 조회(페이지 GET 새로고침)와 문의 경로를 제공한다. 취소 확인 중은 취소 완료와 구분해 계속 조회한다. 재열람 목록은 환불/삭제/종료 기록도 보존해 표시하며 기한은 과거 주문 기록임을 구분한다. 인증된 목록을 열어둔 경우 표시 기한을 주기적으로 재평가한다. 실제 환불·만료 값·DB 권한은 수정하지 않는다.
