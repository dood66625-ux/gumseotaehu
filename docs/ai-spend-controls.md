# AI 비용 원장 연결 후보

`lib/ai-spend-ledger.ts`는 SQLite 트랜잭션으로 주문 ID·버전당 1회 예약과 UTC 일별/원장 누적 예산을 적용하는 미등록 후보입니다. 일반 worker·HTTP 어댑터·공개 API에서는 사용하지 않습니다. 이번 작업에 유료 API 요청·고객 정보 전송은 없습니다. 기존 합성 검증의 4회 제한과 DB도 변경하지 않습니다.

정책 금액은 USD 백만분의 일 단위 정수입니다. 예약액은 최소 $0.06이며 일별/누적 한도는 호출자가 명시해야 합니다. 테스트의 금액은 운영 예산 승인이나 기본값이 아닙니다. 최초 정책을 저장하고 이후 다른 값으로 여는 것을 거부하며 호출자 객체 변경도 반영하지 않습니다.

예약 후에는 상태·날짜와 관계없이 같은 주문·버전의 재예약을 거부합니다. UUID 대소문자도 같은 주문으로 취급합니다. 별도 DB 연결·재시작에서도 원장이 유지되며 예약은 `BEGIN IMMEDIATE`로 직렬화합니다. 비용 노출은 예약액과 확인된 추정 사용액 중 큰 값으로 계산하고, 지연·중복 사용량 콜백이 더 작은 값을 보내도 줄이지 않습니다. 사용량 없이 완료 처리할 수 없습니다. 응답 유실은 uncertain으로 남기며 자동 재호출·예산 환급·조용한 해제를 제공하지 않습니다.

이 한도는 제공자 청구의 하드캡이 아닙니다. 향후 어댑터에서 입력·출력·모델 가격의 상한을 예약액에 맞춰 제한하고, 예약을 네트워크 요청 전에 내구성 있게 기록해야 합니다. 주문 버전·시간·예산을 고객 요청에서 받지 않고 서버의 권위 있는 데이터로 결정해야 합니다. 실패·환불·삭제·복원·버전 재작성과의 통합 검증, 실제 정책 결정, 별도 활성화 승인이 남아 있습니다. DB 자체가 과거 사본으로 복원되거나 원장이 삭제되는 경우의 중복 청구 방어는 이 후보만으로 보장하지 않습니다.

검증: 별도 DB 연결 재예약, 응답 유실 보류, 일별/누적 한도, 지연 사용량, 정책 불변, 잘못된 입력 등 6개 오프라인 테스트. 네트워크나 고객 키가 필요하지 않습니다.

## 생성 흐름 연결 후보

`runBudgetedAiJob`은 기본 비활성이며 명시한 주문 한 건만 처리합니다. 서비스가 DB에서 읽은 주문 ID·버전을 동결된 생성 문맥으로 넘기고, 원장 예약을 마친 뒤에만 주입된 생성기를 호출합니다. 사용량 콜백은 응답 파싱·해석 검증 전에 추정 비용을 기록해야 합니다. 콜백 없이 반환한 보고서, 다른 제공자, 계산/본문 검증 실패, 보고서와 사용량의 비용 불일치는 저장하지 않습니다. 기록된 추정 비용은 저장 보고서 사용량에도 반영합니다.

응답 유실이나 실패 후 재예약이 거부되어 후속 큐 시도가 생성기를 재호출하지 못합니다. 실패한 큐의 기존 재시도/실패 상태 전환 자체는 유지됩니다. 생성 도중 환불된 주문은 기존 저장 직전 권한 검사로 게시를 막으며 예약 비용을 반환하지 않습니다. 프로세스가 응답 뒤 저장 전에 중단되면 예약은 남고 자동 재호출하지 않으므로 관리자 확인 절차가 필요합니다.

이 후보는 실제 OpenAI HTTP 전송기나 일반 worker에 등록되지 않았습니다. 향후 운영 연결 시 체험/AI 큐 분리, worker 간 배타적 처리, 오류별 관리자 복구와 고객 안내, 신뢰 가능한 추정 가격·사용량 전달, 원장 복원 보호를 추가해야 합니다. 별도 DB에 원장을 두는 경우 원장과 보고서의 원자적 커밋을 보장하지 않으며, 공개 경로가 arbitrary generator를 주입할 수 있도록 노출하면 안 됩니다.

비용 원장 6개와 비동기 생성 통합 16개(총 22개)가 통과했습니다. 기본 비활성, 저장/재열람, 사용량 반영, 응답 유실 재시도, 한도 도달, 잘못된 본문, 사용량 누락, 생성 중 환불을 합성 정보와 모의 생성기로 검증했으며 실제 유료/메일/결제 요청은 없습니다.
